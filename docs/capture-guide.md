# 接网与抓取作业流

目标只有一件事：**拿到 Windows 官方驱动打印一页 A4 时吐出的那串原始字节**。
其余都是准备工作。下面按"必须做"和"按情况选"分开，别从头顺读。

---

## 一、必须做：把打印机接入网络

2323AM 的接口是 USB 2.0 + 10/100BASE-TX 以太网，没有内置无线。

**1. 接线**

网线从打印机背后 LAN 口接到交换机或路由器任意 LAN 口。不建议直连电脑网口——
那需要手工配同网段 IP，多一层故障点。如果办公网口不够，用一个几十块的千兆交换机分出来即可。

**2. 取 IP（最省事的顺序）**

先打印一张**配置页**，上面直接写着 MAC、IPv4 地址、是否 DHCP：

> 面板 → `用户功能 / User Functions` → `列表打印 / Reports` → `配置页 / Configuration`

拿到 IP 后，到路由器/DHCP 服务器按 MAC 做一次**地址保留**。这一步很重要：
后面要反复打印十几份做差分对比，IP 中途一变，抓包全部作废。

**3. 验证**

```bash
ping 192.168.1.50
python tools/probe_printer.py 192.168.1.50
```

`probe_printer.py` 要看到 **9100 端口可连接**。如果只有 515（LPR）通、9100 不通，
代理方案要改成 `--port 515` 并把驱动端口类型换成 LPR——告诉我就行。

> 你已经确认这台机器不吃 IPP/PCL，所以这里不用再试通用驱动，直接走逆向。

---

## 二、装 Windows 官方驱动（抓数据的前提）

驱动包从东芝官网对应区域站点取，**不要用国内下载站**（捆绑投毒是真实风险）。
安装时如果安装程序强制"搜索网络打印机"，让它搜、搜到后建好队列，再把队列的端口改掉（见下）。

记下驱动版本号（打印机属性 → 关于），不同版本的报文可能不一样，这份记录要放进 `docs/protocol-re.md` 抬头。

---

## 三、抓数据：三条路，按省力程度排序

### 路线 A：打印到文件（首选，不碰网络、不用抓包）

Windows 自带"打印到文件"，能把驱动生成的字节流原样写成文件。

1. 控制面板 → 设备和打印机 → **添加打印机** → 我需要的打印机不在列表中
2. 选 **通过手动设置添加本地打印机** → **创建新端口** → 端口类型选 `Local Port`
3. 端口名填一个文件路径，例如 `C:\captures\white.prn`
4. 驱动选东芝 e-STUDIO2323AM（已装的话直接选）
5. 打印任意文档 → 输出就是 `C:\captures\white.prn`

或者更灵活：端口类型直接选 **`FILE:` (打印到文件)**，每次打印会弹窗问文件名，
一份文件一个名字，不会互相覆盖。**多份差分对比时用这个。**

注意事项：

- 这个队列的驱动设置就是数据来源，所以要**固定**：A4、600dpi、单面、普通纸、关省墨。
  每改一个变量存一份文件，正好对应 `docs/protocol-re.md` 的用例表。
- 文件端口下驱动可能弹"打印机脱机/无法获取状态"。**忽略它，文件照样有内容。**
  如果文件是 0 字节，才说明该驱动在文件端口下拒绝工作，转路线 B。

### 路线 B：本地 9100 代理（要保留真实网络行为时）

本仓库自带 `tools/port9100_proxy.py`，已通过离线自测（字节级一致、双向回读落盘）。

```bash
# 1. 起代理（前台保持运行）
python tools/port9100_proxy.py --target 192.168.1.50 --label white

# 2. 把打印机队列的端口改成 127.0.0.1:19100
#    打印机属性 → 端口 → 添加端口 → Standard TCP/IP Port → 地址填 127.0.0.1
#    （Windows 若拒绝 127.0.0.1，填本机局域网 IP；代理监听 0.0.0.0）

# 3. 打印一页，代理自动落盘并打印头部判断
```

产物在 `captures/`：

| 文件 | 内容 |
|---|---|
| `white.bin` | **驱动 → 打印机，就是要逆向的作业流** |
| `white.back.bin` | 打印机 → 驱动，PJL 状态回读，字段线索 |
| `white.meta.json` | 字节数、SHA256、头部 hexdump、头部判断 |

代理会当场打印前 64 字节和一句判断（`UEL + PJL / 语言=GDI` 之类）。
**这一句就能确认驱动到底用 PJL 还是裸私有格式**，比事后分析快得多。

### 路线 C：Wireshark

只在 A、B 都拿不到数据时用。过滤 `tcp.port == 9100`，右键任一包 →
Follow → TCP Stream → Show data as Raw → Save as。要注意 TCP 分段和截断，
不如前两条干净。

## 四、要抓哪几份

不用抓满 18 条。先抓这 6 份，足够判断压缩方式和作业结构：

| 顺序 | 文件名 | 驱动设置 | 要回答的问题 |
|---|---|---|---|
| 1 | `white` | A4 / 600dpi / 单面 / 全白页 | 一页空页有多少字节 → 压缩率量级 |
| 2 | `black` | 同上 / 全黑页 | 全黑与全白的差值 → 是否行程编码 |
| 3 | `checker` | 同上 / 1px 棋盘 | 高频内容是否膨胀 → 有无字典压缩 |
| 4 | `single` | 同上 / 只有 1 个黑点 | 位图起点偏移、行对齐方式 |
| 5 | `text` | 同上 / 一页正文 | 真实文档的典型体积 |
| 6 | `duplex` | A4 / 600dpi / **双面长边** / 同第 5 份 | duplex 字段位置（本机已装 MD-0107） |

全白/全黑/棋盘的生成器已经有了：

```bash
make test && ./test_enc --patterns patterns
```

生成的是 PBM，用任何看图工具转成 PDF 后打印即可；或者直接用 Word 画 1×1 表格铺满。

## 五、抓完立刻做的两件事

```bash
# 1. 压缩率量级：这个数字决定后面是写编码器还是直接拼原始位图
python tools/analyze_stream.py --stats captures/white.bin --page a4-600

# 2. 差分：定位第一处差异的绝对偏移，正好是字段所在位置
python tools/analyze_stream.py --diff captures/text.bin captures/duplex.bin
```

`--stats` 输出的 `实测/理论` 若在 0.7 以上 → 基本没压缩，直接拼原始位图就能打；
若小于 0.1 → 强压缩，必须逆出算法。
